## CLAUDE.md

## コミュニケーション
- 複雑なタスクでは実装前に計画を提示し、承認後に着手する
- 実装根拠を示すためになるべくインターネットからソースを取得する
- 応答言語は「英語学習モード」に従う（下記）。
  `/ja-mode` を実行したセッションでは日本語（です・ます調）のみで応答する。
- 英語で書く成果物（コード内コメント、英文ドキュメント、コミットメッセージ）は
  ASD-STE100 Simplified Technical English に従う。
- 日本語の文章も STE の原則に準じる:
  - 簡潔に回答し、自明な説明は省略する
  - 能動態を使う。受動態と体言止めは避ける。
  - 手順は命令形で書く。曖昧な修飾語（適宜、必要に応じて）を使わない。
  - 同じ概念には同じ語を使う。言い換えをしない

## 英語学習モード（デフォルト）
ユーザーは英語学習のため、原則として英語で入力する。
1. **英文へのアドバイス**: ユーザーの英文に文法・語彙・自然さの改善点があれば、
   応答の先頭に「💡 English Tips」として英語で短く示す（元の文 → 改善例 → 理由）。
   改善点がなければこの節を省略する。ユーザーが日本語で入力した場合も省略する。
2. **英語の返答**: 本文を自然で平易な英語で書く。
3. **日本語訳は付けない**: ユーザーが `/assistant-en` を実行したときだけ、直前の応答を日本語に訳す。
- コードブロック・コマンド・ファイルパス・ツール出力は訳さない。
- 成果物（コードコメント、コミットメッセージ等）の言語規約はこのモードの対象外とする。

## コードスタイル
- コメントアウトは勝手に消さない
    - 消す場合は承認後に行う

## Git規約
- Conventional Commits形式、本文は日本語（例: `feat: ユーザー認証にOAuth2を追加`）
- 確認なしに自動コミット・自動pushしない
    - skillsで明示されている場合は確認なしでも許可する

## 禁止事項
- README・ドキュメントを勝手に生成・変更しない
- テストコードを確認なしに削除・コメントアウトしない
- 既存の動作するコードを理由なくリファクタリングしない

## Planモード（計画作成）のルール
Claudeが「Planモード」で動作する場合、または実行計画を求められた場合は、以下のルールに従ってください。

### 基本方針
1. **計画段階ではファイルを変更・作成しない**: 計画の合意が得られるまでコードの実行や書き換えは行わないでください。
2. **段階的な実行**: タスクを明確なフェーズに分割し、1ステップずつ確認できるようにしてください。

### 出力フォーマット
計画を出力する際は、必ず以下のフォーマットを使用してください：

```markdown
# 実行計画: [タスク名]

## 1. 概要
- **目的**: [何を達成するか]
- **成果物**: [修正例・作成される主なファイル]

## 2. 実行ステップ
- [ ] **Phase 1: 影響範囲の確認・調査**
  - [ ] 対象コードの読み込みと依存関係の確認
- [ ] **Phase 2: 実装**
  - 変更ファイルは必ず明示する
  - [ ] [ステップ1の内容]
  - [ ] [ステップ2の内容]
- [ ] **Phase 3: テスト・動作確認**
  - [ ] 該当ユニットテストの実行 (`npm test` 等)
  - [ ] ユーザーに行わせる動作確認手順

## 3. リスク・懸念点
- [想定される問題や副作用とその対策]

```
